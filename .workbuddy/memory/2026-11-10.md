## 21:05 下拉框输入优先级（所有谱面编辑器）

**需求**：下拉列表盖住按钮时，点按会同时触发列表项与下方按钮。要求下拉框优先：
展开期间全部冻结、点列表外「收起并吞掉点击」。用户后续强调「应用到所有谱面编辑器」。

**用户确认的三点**（AskUserQuestion）：
- 屏蔽范围：全部冻结（按钮 / track 滚动按钮 / 网格点击）
- 外部点击：收起并吞掉本次点击
- 作用范围：063 / 073 + 新版 1.0.4-Kathy + 1.0.4-Official（即 ChartingRouter 全部 4 个）

**根因**：`FlxUI.forceFocus(b, this)` 对制谱器无效（不是 FlxUIState，按钮是普通
`FlxButton` / 自绘 `StyledButton` / `PsychUIButton`）；flixel 输入是各对象自检测，
没有按 z-order 消费事件的机制。063/073 现有 `blockInput` 只冻住网格与键盘，
按钮点击仍由 flixel 自己分发，完全绕过它。

**方案**：新增 `source/backend/ui/DropdownInputPriority.hx` 全局守卫
- 静态 `openMenus:ObjectMap`，`setOpen(menu, bool)` 幂等 / `isOpen()`。
- 懒注册 `FlxG.signals.preUpdate`（已确认 FlxGame.hx:739 早于 `_state.tryUpdate()` 755）
  与 `preStateSwitch`（切 state 清空冻结记录）。
- 冻结时递归遍历 `FlxG.state`（duck typing 取 `members`，避开 FlxTypedGroup 泛型），
  把非「展开下拉框子树」的可交互控件 `active=false` 并记录原值；收起后在**下一帧**
  `restore()` 还原原值 —— 这个帧边界天然实现「吞掉本次点击」。
- `isInteractive()`：FlxButton / FlxUIButton / FlxUICheckBox / FlxUIInputText /
  FlxUINumericStepper / StyledButton + duck typing（onClick / onUp / hasFocus），
  覆盖三套 UI 且不反向依赖编辑器包。
- 展开中的下拉框整棵子树（含 list items / header）豁免，选择功能不受影响。

**接入**：
- 三套下拉框：`FlxUIDropDownMenuCustom.showList/destroy`、
  `PsychUIDropDownMenu.showDropDown`、`VUIDropDownMenu.showDropDown` 调 `setOpen`。
- 四个编辑器各一行：063/073 纳入 `suppressMouse`；新版 / vanilla104 纳入
  `ignoreClickForThisFrame`（该变量在 update 末尾重置，开头置 true 可覆盖整帧）。
- 触控：`PsychUIButton.update()` 开头 `if (!active ...) return`；StyledButton 的 update
  由 group 分发，`active=false` 同样屏蔽；移动端主触点走 `FlxG.mouse` ✓。

**未覆盖**：新版顶部的 HaxeUI 菜单栏是另一套输入系统（`MouseHelper`），不在
flixel active 冻结范围；它已有独立的 `haxeMenuOpen / haxeMenuIgnoreFrames` 保护。

**验证**：windows `--no-output` / android `release.hxml` 均 EXIT=0；各文件换行符保持。

## 移动端下拉列表触控滑动 —— 排查与守卫加固

用户问：063/073 移动端「点开下拉栏后上下滑动」在守卫上线后是否仍正常。

**结论：正常**，证据链（静态核对）：
- `FlxUIDropDownMenuCustom extends FlxUIGroup`，构造里 `add(header)` /
  `add(dropPanel)` / `add(list[i])` 全在 `members` 中 → `collectSubtree()` 整棵
  标 protected，`active` 不会被守卫改动。
- 父链 `state → add(UI_box) → FlxUITabMenu.addGroup()` 内部确实 `add(g)` →
  `tab_group_song → dropdown`，`members` 递归可达。且 `FlxUITabMenu` /
  `FlxUIGroup` / `FlxUI` 都没有 `onClick`/`onUp`/`hasFocus` 字段，
  `isInteractive()` 不命中 → 父容器不冻结，`update()` 链完整。
- 滑动在 `FlxUIDropDownMenuCustom.update():515` 读 `FlxG.swipes`；该数组由
  `FlxTouch.hx:90`（抬手）/`FlxMouseButton.hx:43` push，`FlxGame.hx:763` 在
  `_state.tryUpdate()` **之后**才 pop 清空 → 与任何对象 `active` 无关。
- `FlxG.mouse.overlaps(this)` 对 group 走 `FlxObject.overlaps:981` 的
  `group.any(...)`，展开时 dropPanel + 可见列表项覆盖列表区域 → 手指在列表上
  起手不会触发 `showList(false)` 提前收起。
- 063/073 新增的 `isOpen()` 只进 `suppressMouse` / `blockInput`，管网格点击
  与键盘，不碰 swipes。项目内 `FlxG.swipes` 仅此一处消费，无争抢。

**顺手加固守卫两个真实隐患**（都只改 `DropdownInputPriority.hx`）：
1. `isInteractive()` 是 duck typing，任何**容器**若将来带 `onClick` 等字段会被
   冻结；而 flixel 的 `active=false` 会阻止 FlxState/FlxGroup 下传 `update()`，
   下拉框滑动会直接停摆。新增 `markAncestors()`：把「路径上能到达受保护对象」
   的祖先标为 `keepActive` —— 只保活、不跳过递归（否则同页签被盖住的按钮会
   逃过冻结）。`collectSubtree` 的 protected = 整棵子树放行，两者语义分开。
2. `sync()` 原来只在冻结布尔翻转时重算。同一帧内 A 收起 + B 展开时布尔不变
   → 不重算 → B 的列表项沿用 A 那轮的冻结状态，导致 B 不能点也不能滑。
   改为用 `lastOpen` 记录展开集合、`sameSet()` 检测变化，变化即
   `restore()` 后按新集合重新冻结；无变化仍走轻量路径，不增加每帧开销。

**验证**：windows `--no-output` / android `release.hxml` 均 EXIT=0；Python 复刻
树结构自检：下拉框 8 个节点的 update 链全 `active=True`，冻结集合恰好是
同页签按钮 / tab 按钮 / 网格按钮 / StyledButton 四个「其它」控件。
