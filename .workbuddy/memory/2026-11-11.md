连容器一起冻，整个编辑器只剩 HaxeUI（独立输入系统，不受 flixel 冻结）能用。
实测证明这个语义不合适，需求应收敛为「只冻结被列表覆盖的区域」。

### 改动

`DropdownInputPriority.hx`：
- 新增 `pointerInsideOpenList()` / `computePointerHit()` / `hitSprite()`：
  用 `FlxG.mouse.overlaps(o, cam)` 判断指针是否落在**展开列表实际覆盖区**内。
  三路判定兼容三套下拉框：可见的 `_items` / `list` 选项按钮、新版被

  063/073 的 `dropPanel`。

  本帧就 restore 全部控件**。
- `shouldBlockInput()` 改为：展开中只有指针在列表内才返回 true；
  `closing` 标志负责「收起当帧吞掉这一次点击」，下一帧 preUpdate 清除。
  删掉 `closeStamp` / 0.75s 自愈（不再全局冻结，无需）。
- `onPreUpdate()` 每帧清 `hitCacheValid` 与 `closing`。
  时序细节：preUpdate 早于 `updateInput()`，鼠标位置还是上一帧的，所以
  `sync()` 用**不缓存**的 `computePointerHit()`；每帧缓存由 state.update()
  期间第一个控件调用 `pointerInsideOpenList()` 生成，那时输入已刷新，
  保证控件闸门用的是当前帧位置。
- 位置判定每帧只算一次并缓存，避免 N 个控件各遍历一遍列表项。

4 个编辑器各 1 处：`DropdownInputPriority.isOpen()` →
`DropdownInputPriority.pointerInsideOpenList()`
（063 的 `suppressMouse`、073 的 `suppressMouse`、新版与 vanilla104 的
`ignoreClickForThisFrame`），网格点击也只在列表覆盖区内让位。

### 最终语义

列表矩形**内** → 下拉框优先，下方按钮/输入框/网格让位；
列表矩形**外** → 编辑器完全正常，所有 UI 可操作。

## 新版编辑器下拉框「选中选项后文本框仍处聚焦态」— 已修

两层原因（两套 UI 完全对称）：

1. `PsychUIDropDownMenu` / `VUIDropDownMenu` 的 `clickedOn()` 只做
   `selectedIndex = num; showDropDown(false);`，**没有清静态 `focusOn`**。
   下拉框本体 extends `*UIInputText`，`focusOn == this` 时 caret 继续闪、
   IME 继续激活、还能继续打字过滤。

## 圆角三轮：糊 / 最小化双层框 / 多标签中间圆角

**用户选定**：全关抗锯齿 + 圆角硬边；最小化时背景板只包住 tab 头；
多标签栏首尾圆、中间方；白描边展开保留、最小化隐藏。

**「糊」的真正原因**：圆角是 OpenFL `Graphics.drawRoundRect` 画进 `BitmapData`
再贴到 sprite 的，OpenFL 自带抗锯齿 → 圆角边是一圈半透明像素。
项目里 `FlxSprite.defaultAntialiasing` 本来就是 false（只有 StyledButton 设 true），
所以单关 `sprite.antialiasing` 没用。
- `PsychUIRounded.hardenAlpha(bd)`：全图 alpha 二值化（≥128→255，否则→0），
  用于所有自己烘焙的位图（rounded / sheet / PsychUIBox.bg / PsychUITab）。
- `PsychUIRounded.hardenEdges(bd, band=3)`：只处理位图外圈几条像素，
  用于 HaxeUI `_surface`（它可能有整体半透明底色，全图二值化会破坏底色）。
- 显式 `antialiasing=false`：PsychUIBox.bg / PsychUITab / PsychUIRounded.apply() /
  自绘图标帧（checkbox、radio、stepper ±、dropdown 箭头、radio 上下箭头）/
  ◀▶ 平移按钮 / HaxeUI 菜单条与按钮与下拉项。

**HaxeUI 硬边**：后端把圆角画进私有 `_surface:FlxSprite` 的 pixels，
用 `Reflect.field(comp,'_surface')` 取，`preDraw` 时按「待处理」标记统一
`hardenEdges` + `dirty=true`。标记在 applyTopBarTheme / styleMenuComponent /
setMenuButtonHighlight / 各 hover·down·up 回调 / MENU_OPENED·CLOSED 里置位。
回调必须存成字段 `_haxeUIHardEdgeCallback` 再 add/remove
（hxcpp 上 FlxSignal 按引用比较，重复取 bound method 会 remove 不掉）。

**最小化双层框**：`set_isMinimized` 原来把圆角板重烘焙成 `tabHeight+20=40`，
tab 头只有 20，下面留 20px 黑空带；加上 bg 的 2px 白描边整圈包住，
与选中/悬停 tab 的浅灰高亮叠成双层框。
现在：`bakeRoundedBg(_boxWidth, tabHeight, false)` —— 高度=20、
不画白描边（新增 `withBorder` 参数与缓存 key 的 b0/b1 位）；展开时恢复
`_originalHeight` + 白描边。**方角皮肤分支仍用 `tabHeight+20`，其它编辑器不变。**

**多标签**：`PsychUITab` 新增四角独立开关 `roundTopLeft/TopRight/BottomLeft/BottomRight`，
用 `drawRoundRectComplex` 按开关画，缓存 key 带 flags。
`PsychUIBox.updateTabs()` 按 index 设置：只有第一个 tab 左上圆、最后一个右上圆，
中间全方角；最小化时首个补左下、末个补右下，让整条收成一枚完整圆角条。
`set_isMinimized` / `setCornerRadius` 都会重跑 `updateTabs()`
（前者仅在 `cornerRadius>0` 时，避免影响其它编辑器）。

**验证**：Windows / Android `release.hxml` +
`include('states.editors')` + `include('backend.ui')` 双目标 EXIT=0；
换行符保持（PsychUIBox.hx CRLF，其余 LF）。
**待用户复测**：圆角是否变成干净硬边；最小化时是否只剩一条圆角标签、无黑空带与双层框；
展开时白描边是否还在；多标签中间是否方角、首尾是否圆；
硬边后中文文字（保留抗锯齿）与图形是否观感协调。

## box 最小/最大化过渡动效（用户未给细节选项，按合理默认直接实现）

`PsychUIBox.hx` 新增 `minimizeDuration`（默认 **0 = 立即切换**，其它编辑器/旧行为完全不变）。
`ChartingState.applyChartBoxRoundedStyle()` 末尾设为 `0.22s`；
`bgFollowsSelectedTab` 为 true 的 `upperBox`（文件/编辑/视图菜单底板，二十多处
`isMinimized = true` 调用）显式设 0，保持即时收起，菜单交互不受动画拖慢。
换肤函数里**先** `if (wasMinimized) isMinimized = true` **再**设 duration，
所以进编辑器时不会意外播一段收起动画。

核心实现（都在 `PsychUIBox.hx`）：
- `set_isMinimized()` 改写成「启动/打断动画」，起点取 `bg.height`（或进行中的
  `_animHeight`），目标 `minimizedHeight()`（圆角=tabHeight 20px，方角=+20）。
  反向触发会从当前显示高度接着走，不会跳。
- `stepMinimizeAnimation()` 在 `update()` 开头推进；收起 `easeOutCubic`、
  展开 `easeOutBackSoft`（easeOutCubic + 末段 20% 的 2% 正弦鼓包，
  避免标准 easeOutBack 第一帧就从 20px 弹到 120px）。
- 高度**量化到 8px 一档**再 `bakeRoundedBg()`，靠已有的尺寸缓存复用：
  一次动画约 11~12 个档位，往返第二次起零烘焙。≤40px 不量化（否则 20px 会被量化成 24px）。
- 性能：`bakeRoundedBg` 的 `hardenAlpha()`（全图逐像素）换成
  `hardenEdges(bd, max(6, cornerRadius*2+2))`——AA 只在轮廓/圆角弧附近，
  结果等价但每帧烘焙快一个数量级。
- 动画全程带白描边，收起终态才切无描边；`updateTabs()` 用
  `isMinimized && !_animActive` 决定底角，收起完成才补圆。
- `menuVisibleDuringAnim()`（`!_animActive || _animProgress >= 0.55`）：
  展开过半才让内容出现，避免内容飘在还没长起来的小框外；收起时内容按原逻辑即时隐藏。
- `bgFollowsSelectedTab` 分支加 `!_animActive` 守卫，避免菜单底板每帧覆盖动画高度；
  `resize()` / `setCornerRadius()` / `destroy()` 都会终止动画并落到终态。

**自检**：Python 模拟 60fps/0.22s → 收起 15 帧 12 档单调 360→20，
展开 15 帧 11 档 20→…→360→368→360（8px 轻回弹）。
**验证**：Windows / Android `release.hxml` + 双 `include(...)` 全量 `--no-output` 均 EXIT=0；
`PsychUIBox.hx` 保持 CRLF(515/515)、`ChartingState.hx` 保持 LF。
**待用户复测**：双击/单击 tab 的收起展开手感、回弹幅度是否合适、
收起时内容「瞬间消失」是否想改成淡出/随高度裁切、收起完成瞬间白描边消失是否会闪。
可调参数集中在 `minimizeDuration`(0.22)、`ANIM_HEIGHT_QUANT`(8)、`easeOutBackSoft` 的 0.02。
