## 追加：StyledButton 性能优化（backend/ui/StyledButton.hx）

用户问性能可改善处。查 flixel 5.9 源码后的结论与原实现的问题：
- `FlxG.bitmap.add(..., Unique=true)` → `FlxGraphic.getBitmap()` 会 **clone 整张 BitmapData**；
  即 `loadGraphic(sheet, true, s, s, true)` 每按钮多一份位图拷贝，且原始 sheet 立刻变垃圾。
- `fromBitmapData` 里 `findKeyForBitmap()` 是遍历整个图形缓存的 O(n) 扫描；传 `FlxGraphic` 可绕过。
- `unique=true` 生成随机 key，每次 rebuild 换肤都会在 BitmapFrontEnd 里留下一个永不释放的 FlxGraphic（泄漏）。
- `FlxSprite.update()` 每帧调 `animation.update()`，三个单帧动画白跑；静止时 animateScale 仍每帧写 scale。

改动：
- 共享纹理：key = `Reflect.fields(style)` 排序后全字段 + direction + cacheTag；
  命中 `FlxG.bitmap.get(key)` 就完全跳过矢量烘焙，直接 `loadGraphic(graph, ..., unique=false, key)`。
  同 graphic + 同 tileSize 会连 `FlxTileFrames` 一起共享。
- 去掉 `unique=true` 的 clone；换肤/销毁时释放独占纹理，不再累积。
- 三态改用 `animation.frameIndex` 直接切帧，不再 add 三个单帧动画 + play。
- `bakeSheet()` 复用同一个 Shape / Matrix（原来每态 new 一个 + 3 个 Matrix）。
- `animateScale()` 到位后吸附停止写 scale（阈值 0.002）。
- 新增 `useSharedCache` / `cacheTag` / `clearCache(disposeGraphics)`；
  自定义 `iconPainter` 默认走独占纹理，给相同 cacheTag 才能共享。

关键源码事实（以后别再踩）：
- `FlxGraphic.fromGraphic(Source, false, key)` 在 `!Unique` 时直接 `return Source`，不查 key。
- `generateKey(systemKey, userKey, false)` 有 userKey 时直接返回 userKey → 稳定 key 可共享。
- `FlxSprite.set_frame()` 会 `frame.copyTo(_frame)` / `clipTo`，`destroy()` 销毁的是私有 `_frame` 副本，
  **共享 FlxFramesCollection / FlxFrame 不会被单个 sprite 的 destroy 破坏**，共享纹理是安全的。
- `FlxGraphic.isDestroyed` 判据是 `shader == null`；引擎清过缓存后需重新烘焙。

未做（收益/风险比不高，除非将来按钮数量到几十个）：
多点触控目前每按钮独立遍历 `FlxG.touches.list` 并各算一次 getViewPosition，可做静态每帧分发；
隐藏按钮仍会跑 super.update()，可让调用方把 active 与 visible 同步；
三态仍是 3 帧位图，改单帧 + colorTransform 可再省 2/3 显存但会改变视觉。

验证：`haxe export/release/android/haxe/release.hxml --macro "include('states.editors.old')" --macro "include('backend.ui')" --no-output` 通过（EXIT=0）。

## 追加：新版制谱器 dragPreview 同类透明色修复 + 全库 6 位颜色判定结论

全库排查 6 位 `0xRRGGBB` 的结论（重要，避免以后误改）：
- **真 bug 只在 `makeGraphic` / `FlxGraphic.fromRectangle` 路径**：它们把颜色直接交给
  `new BitmapData(w, h, true, Color)`，缺 alpha 即全透明。全库只剩上面这一处。
- **tint 路径无害**：项目覆写版 `source/flixel/FlxSprite.hx:1011` 的 `updateColorTransform()`
  只用 `color.redFloat/greenFloat/blueFloat` + sprite 的 `alpha`，不读颜色自身的 alpha 字节。
  所以 `replayButton.color = 0xFF7D00`（FreeplayState.hx:630）、`color:FlxColor = 0xffffff` 默认值、
  `FlxVirtualPad.createButton(..., 0xRRGGBB)` 都不会变透明，不要改。
- **OpenFL Graphics 路径无害**：`beginFill/lineStyle` 只吃 RGB，`HitGraph.AXIS_COLOR = 0xffffff`
  用于 `gfx.lineStyle(1, AXIS_COLOR, AXIS_ALPHA)` 是对的。
- 需逐个确认（暂未动）：`ClientPrefs.simpleInfoColor = 0x000000` 默认值会被
  `previewText.setFormat(...)` / `previewText.color` 使用，但多数读取处手动重组 RGB；
  `RatingCounter.COLOR_PERFECT = 0xFFC0CB` 用于评级文字色。
