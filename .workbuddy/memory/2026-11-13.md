# 2026-11-13 工作日志

## 修复 Release workflow 的 macOS/iOS 编译 + 新增纯构建 workflow
承接 11-12 的排查（run 43216067444：三个 macos-15 job 因 arm64 runner 容量不足被 cancelled，Release 因下载不存在的 `macOSBuild-x86_64` 失败并连带跳过全部发布步骤）。

- `.github/workflows/release.yml`（已改）：
  - `build-macos-x64` 与 `build-ios` 的 `os` 从 `macos-15`（arm64 M1）改为 **`macos-15-intel`**（Intel 4C/14G）；只有 `build-macos-arm64` 继续留在 arm64 池，把并发抢 runner 从 3 个降到 1 个。iOS 编译不依赖主机架构。
  - 六个 `Download *` 步骤的 `if` 从只看 `inputs.*` 改为 `inputs.xxx && needs.build-xxx.result == 'success'`，并加 `continue-on-error: true`：构建被 cancelled/failed 时不再去下载不存在的 artifact，单个产物缺失也不会带崩其余平台发布。
  - `Compress & Prepare` 改 `pack()` 函数 + `ls -A` 非空判断，避免下载失败留下的空目录被 7z 打成空包。
  - `Build file list` 改 for 循环收集（规避 bash -e 下 `[ -f ] && ...` 末尾返回 1 的隐患），并在 `files` 为空时 `::error::` + exit 1，防止创建空 Release。
- 新建 `.github/workflows/build-only.yml`（name `Build Only`）：`workflow_dispatch` 六平台 boolean 勾选（默认 windows/linux/android=true，macOS/iOS=false），复用 `build.yml`，**不创建 Release、不打 tag、不需要 commit-info**；另有 `finalBuild` 开关控制是否附加 `-final -D officialBuild`；末尾 `summary` job 用 `always()` 输出各平台 result 与 artifact 名的表格到 `$GITHUB_STEP_SUMMARY`。产物在 Actions 运行页 Artifacts 下载。
- `main.yml` 未动：它是已有的「全平台无选项 dev 构建」，与新文件并存，后续可考虑删除或改为 push/PR CI。
- 验证：`actionlint v1.7.12`（临时下载到 temp 目录，未污染项目）对两个文件 EXIT=0；两个文件所有 `run: |` 块提取后 `bash -n` 通过。未实际在 GitHub 上跑 CI。
